# FocusFlow architecture

## Request and identity boundary

Spring Security authenticates each protected request from a signed access token. The application never accepts an owner identifier from the browser: controllers resolve the authenticated user and repositories include that owner in every task and list lookup. A valid identifier belonging to another account therefore produces the same not-found boundary as an unknown identifier.

Passwords are BCrypt hashes. Refresh tokens are opaque random values; only their SHA-256 digests are stored. Refreshing revokes the previous token and issues a new pair, while logout revokes the supplied refresh token.

## Offline synchronization

1. The browser applies a mutation to its user-scoped local snapshot.
2. A durable operation is added to the local sync queue.
3. Repeated updates for the same task are coalesced.
4. When online, operations are replayed sequentially.
5. Successful operations are removed; retryable failures remain visible through the sync indicator.
6. The client pulls the authoritative server snapshot after the queue drains.

Task IDs are generated by the client. `clientRequestId` makes create retries idempotent. JPA `@Version` allows the API to reject stale writes with HTTP 409 instead of silently overwriting a concurrent update.

Local data, active-list state, and queued operations are partitioned by user ID. Offline guest mode uses a separate namespace so one account cannot see another account's cached workspace.

## Data lifecycle

Deletes first set `deletedAt`. Normal queries exclude deleted rows, the trash view includes them, and users may restore or permanently delete their own tasks. Removing a custom list moves its tasks to the user's Inbox to avoid accidental data loss.

Flyway owns the PostgreSQL schema. Hibernate validates rather than mutates that schema at runtime. H2 is restricted to tests and the explicit `demo` profile.

## Operational model

- Nginx serves immutable frontend assets and falls back to `index.html` for client routing.
- Spring Boot exposes liveness/readiness health groups and Prometheus metrics.
- Docker health checks gate frontend and monitoring startup on backend readiness.
- CI verifies the two applications independently, builds both images, scans the repository, and runs CodeQL.

For a public environment, keep PostgreSQL and the actuator endpoint on private networks, terminate TLS before the frontend/API, inject secrets through a managed secret store, and add centralized logging, distributed rate limiting, backups, and alert routing.
